# Analytic Topic Service

Поиск публичных видео YouTube и описательная аналитика каналов для исследования тем видеоконтента. Сценарий: найти видео, изучить выборку его канала, вернуться к выдаче.

Сервис считает медиану, среднее, разброс просмотров и числовые отношения. Не выдаёт оценочные вердикты успешности, не обещает рост и не представляет накопленные просмотры как текущую динамику.

Реализован backend и frontend-поиск: форма с draft/applied, первая страница карточек, явные обновление/повтор и безопасный API-клиент. Работают явная пагинация, дедупликация и локальная сортировка загруженных видео. Подключены ограниченный сессионный кеш и восстановление выдачи/прокрутки; экран аналитики показывает ограниченную выборку, описательные показатели, график и исходные данные. Базовый браузерный сценарий с тестовым API проверен на 1440/390/320 px; физические устройства и полная доступность остаются отдельной проверкой.

## Стек и устройство

- Backend: FastAPI, SQLAlchemy, SQLite; дальнейший переход на PostgreSQL предусмотрен моделями, но подключение не проверено.
- Источник: YouTube Data API v3, только публичные данные.
- Frontend: Vue 3, TypeScript, Vite, Vue Router, Pinia, Tailwind, Naive UI; ECharts строит SVG-график просмотров выборки и линию медианы.

```text
frontend (Vue foundation) --typed REST client--> backend (FastAPI)
                                              -- DataSourceAdapter -> YouTubeAdapter
                                              -- SQLite: channels / videos / snapshots / channel_analyses
```

`DataSourceAdapter` отделяет источник от вычислений. Поисковые записи не подменяют подтверждённую выборку загрузок канала. Поисковая страница использует типизированный API-клиент; анализ из карточки открывает конкретный канал с ограниченной выборкой, графиком и точными исходными значениями.

## Локальный запуск

Нужен Python 3.10+; текущая проверка выполнена на Python 3.14. Для миграции старой SQLite нужна SQLite 3.35+.

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
# Если .env ещё не существует:
test -f .env || cp .env.example .env
```

Настройте `YOUTUBE_API_KEY` в локальном `backend/.env` или серверном окружении. Ключ не нужен для тестов, `/api/health` и просмотра схемы. Без настроенного источника поиск возвращает 503. Персональный ключ через `X-YouTube-Key` пока не поддерживается.

По умолчанию используется `backend/app.db`. Для другой БД задайте `DATABASE_URL` на сервере. Ключ и `.env` не должны попадать в Git, URL клиента или сообщения об ошибках.

SDK использует встроенный discovery; API-вызовы идут через HTTPS `https://www.googleapis.com/`. Проверка сертификата и имени хоста включена. Таймаут сокета — 15 секунд; это не общий предел времени всей операции.

### Новая БД

```bash
python -m app.migrate
python -m uvicorn app.main:app --reload
```

API: `http://127.0.0.1:8000`, документация: `http://127.0.0.1:8000/docs`.

### Существующая SQLite

Импорт/startup не пересоздаёт и не мигрирует таблицы. Сначала проверьте схему и выполните явную миграцию с резервной копией:

```bash
python -m app.migrate --check
mkdir -p ../backups
python -m app.migrate --backup ../backups/before-v2.sqlite3
```

Имя резервной копии должно быть новым; существующий файл не перезаписывается. Миграция сохраняет строки, добавляет числовую длительность и подтверждённый кеш анализа, удаляет прежнюю недостоверную классификацию видео. Известные числовые длительности сохраняются. Изменения схемы и backfill транзакционные. Для необычной/частичной старой схемы миграция откажется от записи и потребует её проверки.

PostgreSQL-ветка миграции требует заранее созданной внешней резервной копии и `--backup-confirmed`; реальное подключение и PostgreSQL-драйвер в этой проверке не настраивались.

### Frontend — техническая основа

Проверено на Node 24.19.0. В отдельном терминале из корня checkout:

```bash
cd frontend
npm ci --cache ../.npm-cache --no-audit --no-fund
npm run dev
```

Адрес: `http://127.0.0.1:5173/`. Поиск выполняется явно; для него backend должен быть запущен на 8000. Анализ загружается при переходе на канал, повторно — из сессионного кеша. Это отдельный frontend проекта, не DeepSeek Harness GUI.

В dev запросы `/api` проксируются в backend на 8000. Для production нужен публичный API origin в `VITE_API_BASE_URL`; YouTube-ключ в frontend не переносится. Полная конфигурация, API-фабрики и ограничения: [frontend/README.md](frontend/README.md).

## Основные API

| Эндпоинт | Назначение |
|---|---|
| `POST /api/search/videos` | Необязательная тема, язык-предпочтение, точные интервалы длительности/подписчиков, одна страница поиска |
| `GET /api/channels/{id}` | Подтверждённая ограниченная выборка, описательные показатели, данные для диаграммы |
| `GET /api/videos/{id}` | Необязательная прямая карточка, без сравнения короткого видео с неподходящей выборкой |
| `GET /api/health` | Проверка процесса и версии схемы |

Подробные поля, ошибки, правила пагинации и свежести: [backend/API_CONTRACT.md](backend/API_CONTRACT.md).

Поиск обрабатывает одну страницу до 50 кандидатов. После фильтров карточек может не быть; токен продолжения при этом сохраняется. `relevanceLanguage` не является строгим языковым фильтром, запрос не переводится. Пустая тема проверена на живом источнике (HTTP 200); качество такой выдачи не оценивалось.

Аналитика берёт до 30 последних доступных видео строго длиннее 180 секунд, просмотрев до 200 записей загрузок / четырёх страниц. Неизвестные просмотры не заменяются более старым видео. Размер, даты, причины остановки и пропуски возвращаются явно. Это отбор по длительности, не распознавание Shorts.

Повтор подтверждённого анализа не обращается к источнику. Обновление — только через `force_sync=true`; ошибка не стирает прежний успешный снимок. Клиентский Pinia/sessionStorage-кеш ограничен 5 поисками, 10 анализами и 3 МиБ сериализованного UTF-8 JSON. Экран анализа использует этот кеш и не загружает аналитику для всех карточек выдачи.

## Тесты и контракт

```bash
cd backend  # если вы ещё в корне проекта
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m app.export_contracts
```

Тесты блокируют внешний сетевой доступ и используют подставной источник. Покрываются точные границы, календарные периоды, пагинация, порядок и стоимость пакетных операций, неполные данные, кеш, безопасные ошибки, миграция/откат и сохранность резервной копии SQLite.

`contracts/openapi.json` и `contracts/api.ts` генерируются из одной схемы; тесты обнаруживают рассинхронизацию. Frontend импортирует DTO только как типы; компиляция контракта проверена вместе с `vue-tsc`/`tsc`. Это не полная runtime-валидация JSON и не проверка рендера.

Ограниченная проверка поиска, аналитики и кеша на живых данных: [отчёт](backend/LIVE_TEST_REPORT.md). Это не нагрузочный тест и не оценка всей выдачи. Фактический баланс квоты YouTube и PostgreSQL не проверены. Синтаксическая проверка не подменяет тесты и запуск API.

### Проверки frontend

Из `frontend/`: `npm run typecheck`, `npm test`, `npm run build`. Последний полный прогон этапа 10 — **413 passed**; TypeScript-контракт также скомпилирован. Все API-вызовы в тестах подставные, без YouTube-квоты.

Браузерный стенд этапа 10 прошёл в настоящем Chrome после одобренного расширенного доступа: fixture-поиск/канал/возврат, клавиатура, эмуляция touch и ширины 1440/390/320 px; YouTube не вызывался. 12 PNG и JSON-отчёт сохраняются локально в frontend/verification. Это не screen-reader/WCAG-сертификация или проверка физических устройств. Финальный внешний вид ещё не утверждён. Подробности: [frontend/STAGE_10.md](frontend/STAGE_10.md). Каркас описан в [frontend/STAGE_5.md](frontend/STAGE_5.md); рабочий поиск и три живых API-проверки — в [frontend/STAGE_6.md](frontend/STAGE_6.md).
