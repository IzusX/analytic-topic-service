## Найденная проблема транспорта

Первый HTTP-поиск не получил ответ за 60 секунд. SDK использовал `youtube.googleapis.com`; соединение с этим хостом в текущем окружении также истекало по таймауту при отдельных проверках с корректным CA bundle.

Через `www.googleapis.com` проверенное TLS-соединение работало. Чтение публичного канала `freeCodeCamp.org` с тем же ключом прошло успешно и подтвердило пригодность ключа для API.

Исправлен только транспорт в `app/adapters/youtube.py`:

- общий Google API root `https://www.googleapis.com/` через поддерживаемый SDK `client_options.api_endpoint`;
- пути `/youtube/v3/...` берутся из встроенного discovery — префикс в root не добавляется;
- таймаут сокета **15 секунд**, не общий deadline всей операции;
- проверка CA-цепочки и имени хоста сохранена;
- статический discovery, без сетевой загрузки схемы при создании клиента.

Четыре новых случая проверяют настоящий SDK без исполнения запросов: HTTPS-хост, пути `channels`, `videos`, `playlistItems`, `search`, отсутствие удвоенного префикса, включённую TLS-проверку и таймаут.

Отдельная проверка системного SSL-контекста Python выявила отсутствие доверенного issuer. Это не основание отключать TLS: SDK использует `certifi`, с которым проверка `www.googleapis.com` прошла. Глобальное хранилище сертификатов не менялось.
