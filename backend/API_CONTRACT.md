# API contract 0.2

Контракт backend для будущего клиента Vue. Источник полей — Pydantic/FastAPI, а не отдельные вручную поддерживаемые TypeScript-интерфейсы:

- `contracts/openapi.json` — экспорт OpenAPI.
- `contracts/api.ts` — TypeScript, сгенерированный из того же OpenAPI.
- Обновление: `python -m app.export_contracts` из `backend/`.
- `tests/test_contracts.py` проверяет совпадение артефактов с текущим API.

Экспорт не изменяет БД и не обращается к YouTube. Генерация и совпадение схем проверяются backend-тестами. Компиляция `api.ts` теперь дополнительно проверена в frontend `vue-tsc`/`tsc` через type-only импорт; это не полная runtime-валидация ответов или проверка пользовательских экранов.

## Общие правила

- Сервисный ключ хранится только в `backend/.env` или серверном окружении. `X-YouTube-Key` сейчас не обрабатывается; персональный режим отложен.
- Даты запросов должны содержать timezone. Границы и выходные даты нормализуются к UTC; JSON использует RFC3339.
- Отсутствующие числовые сведения и неопределённые деления — `null`, не ноль.
- `subscriber_count_hidden=true` означает подтверждённое скрытие. `null` не даёт основания писать «подписчики скрыты».
- `view_sub_ratio` — просмотры / текущие подписчики из соответствующего снимка.
- `view_median_ratio` — просмотры / медиана явно указанной выборки. Это другое отношение, без оценочного флага.
- `consistency`, `avg_like_view`, `avg_comment_view` — доли, не готовые проценты.
- `is_shorts`, `is_anomaly`, `verdict` и оценочные пороги удалены из текущего контракта. Длительность не определяет формат Shorts.

## POST /api/search/videos

Пример нового поиска:

```json
{
  "query": "ремонт автомобиля",
  "limit": 50,
  "period": "month",
  "relevance_language": "ru",
  "min_subscribers": 1000,
  "max_subscribers": 100000,
  "duration_ranges": ["3_to_10m", "10_to_30m"]
}
```

### Запрос

| Поле | Правило |
|---|---|
| `query` | Необязательная строка, default `""`, trim, максимум 500 символов; пустое значение не передаёт `q` в YouTube |
| `limit` | Целое 1–50, default 50; кандидаты одной страницы до фильтрации |
| `period` | `all`, `day`, `week`, `month`, `year`; default `all` |
| `published_after`, `published_before` | Необязательные абсолютные границы с timezone; нижняя должна быть раньше верхней |
| `relevance_language` | ISO 639-1 из проверяемого набора, китайские варианты `zh-Hans` / `zh-Hant`; `null` или пустая строка не передаёт параметр |
| `page_token` | Непустой непрозрачный токен до 2048 символов, без пробелов и управляющих символов |
| `duration_ranges` | Объединение выбранных интервалов; пустой список не ограничивает длительность |
| `min_subscribers`, `max_subscribers` | Неотрицательные целые, включённые границы |
| `min_views`, `max_views` | Сохранённые API-постфильтры по просмотрам; не добавляют новые элементы согласованного интерфейса |

Отрицательные числа, дробные/булевы значения числовых фильтров, обратные границы и неизвестные поля дают 422 до вызова источника.

### Точная длительность

| Код | Секунды |
|---|---|
| `up_to_3m` | `[0, 180]` |
| `3_to_10m` | `(180, 600]` |
| `10_to_30m` | `(600, 1800]` |
| `30_to_60m` | `(1800, 3600]` |
| `over_60m` | `(3600, +∞)` |

При активном фильтре неизвестная длительность исключается. Без него такие видео сохраняются. При активном диапазоне подписчиков неизвестные или подтверждённо скрытые подписчики исключаются; число 0 остаётся известным значением.

### Период и продолжение

Сутки — 24 часа, неделя — 7 × 24 часа. Месяц и год вычитаются календарно в UTC, с ограничением отсутствующего дня последним днём целевого месяца.

Если `published_after` не задан и `period` не `all`, сервер рассчитывает абсолютную границу при новом поиске. Ответ возвращает нормализованный запрос в `applied`. Для следующей страницы клиент копирует эти условия и меняет только `page_token`. При относительном периоде пагинация без сохранённого `published_after` отклоняется. При явном обновлении клиент убирает токен и прежнюю нижнюю границу, чтобы пересчитать период; черновик формы при этом не применяется.

API не хранит отдельную поисковую сессию и не выполняет локальную сортировку клиента. Связь токена с применёнными условиями и агрегирование страниц обеспечиваются клиентом; чужой/некорректный токен также может отклонить YouTube.

### Ответ

- `query`, `applied` — фактически использованные условия.
- `videos` — обогащённые совпадения этой страницы, с `duration_seconds` и числовыми отношениями.
- `next_page_token` — продолжение, включая страницу без совпадений после фильтров.
- `items_scanned` — число исходных поисковых записей этой страницы, до обогащения/фильтрации.
- `matched_count` — число возвращённых уникальных видео этой страницы, не общее число совпадений YouTube.
- `fetched_at` — время получения.
- `order="relevance"` — исходный порядок YouTube, не глобальные тренды.
- `quota_used_estimate` — оценка стоимости выполненных операций источника, независимо от оставшегося числа карточек.

Ровно один `search.list` на действие. Нет скрытой догрузки до заполнения сетки. `videos.list` и `channels.list` обогащают пакетами; каналы повторно по одному не запрашиваются. Полученные короткие видео сохраняются, а не удаляются из БД.

## GET /api/channels/{channel_id}

Параметры:

- `force_sync=false` — повторная выдача подтверждённого анализа из кеша; `true` явно обновляет его.
- `source_video_id` — необязательный контекст исходного видео из поиска. Не входит в ключ общего кеша анализа и не вызывает отдельный запрос видео.

### Выборка

Последовательные страницы загрузок канала, не произвольные записи поискового кеша. До 30 последних доступных видео с известной длительностью строго более 180 секунд. До 200 исходных записей загрузок и максимум 4 страницы по 50.

Неизвестные просмотры не исключают подходящее видео из выборки и не заменяются более старым видео с известными просмотрами. В формулах просмотров участвуют только известные неотрицательные значения. Короткие видео сохраняются отдельно от отбора в аналитику.

`sample` содержит:

- `rule` — числовое правило и пределы.
- `selected_count` — количество выбранных видео.
- `metric_count` — количество выбранных видео с известными просмотрами.
- `uploads_scanned`, `pages_scanned` — фактическая работа.
- `unavailable_video_count`, `unknown_duration_count`, `excluded_duration_count` — причины пропусков в полученных страницах.
- `date_from`, `date_to`, `unknown_date_count` — диапазон известных дат и число неизвестных дат выбранных видео.
- `target_reached`, `scan_limit_reached` — достигнут ли целевой объём / технический предел.
- `stop_reason`: `sample_full`, `uploads_exhausted` или `scan_limit`.

Это технические ограничения, не доказательство достаточности данных. Отсутствующий uploads playlist — отдельная ошибка `uploads_unavailable`, не успешная «пустая подтверждённая выборка».

### Метрики и представление

Медиана, среднее, population std, CV = std/mean, максимум/медиана, доля просмотров ≥ половины медианы. Средние like/view и comment/view рассчитываются только по доступным отношениям; `like_view_count` и `comment_view_count` показывают число учтённых отношений.

При нулевой медиане максимум/медиана неопределён; доля ≥ половины медианы остаётся математически определённой. При одной записи std = 0, но резюме не делает выводов о повторяемости. При отсутствии просмотров метрики `null`. `summary` описывает числа, без вердиктов успешности.

`videos` возвращает выбранные видео от старых публикаций к новым. Неизвестные даты идут в конец. Один элемент — одно видео, а не исторический замер просмотров канала.

`source_video.status` — `included`, `duration_too_short`, `duration_unknown`, `not_in_sample` или `channel_mismatch`. Если видео не входит в выборку, возвращается исходный id и известная причина/нейтральное пояснение. Другое видео вместо него не выбирается.

### Кеш и обновление

Подтверждённый анализ сохраняется единым JSON-снимком в `channel_analyses`. Ключ включает источник/сервисный режим, длительность, объём и предел сканирования. Поисковый кеш не считается подтверждённой аналитической выборкой.

Ответ содержит `fetched_at`, `from_cache`, `quota_used_estimate`; попадание в кеш даёт стоимость 0 и не создаёт адаптер. Обновление по таймеру отсутствует. Ошибка явного обновления не перезаписывает предыдущий успешный анализ. Новые поисковые данные не изменяют старый аналитический снимок без его обновления.

Бюджет 5 выдач / 10 анализов / 3 МиБ относится к будущему клиентскому Pinia/sessionStorage-кешу, не к лимиту строк серверной БД. Клиентский кеш, навигация и восстановление пока не реализованы.

## GET /api/videos/{video_id}

Сохранён как необязательный прямой API-эндпоинт, не обязательная страница интерфейса. Поддерживает `force_sync`.

При длительности ≤180 секунд или неизвестной длительности аналитическая выборка не запрашивается и отношение к её медиане не рассчитывается. Для подходящего видео используется подтверждённый анализ канала. Только член выборки получает `view_median_ratio`.

Если видео входит в сохранённую выборку, весь возвращаемый объект видео берётся из того же снимка, что и медиана, даже если поиск уже обновил статистику видео. `fetched_at` и `sample_fetched_at` указывают на этот снимок. Это предотвращает смешение более новых просмотров с прежней медианой. Для обновления всей пары есть `force_sync=true`.

`comparison_status`/`comparison_reason` объясняют отсутствие сравнения. Нет автоматического флага аномалии и порога достаточности.

## Ошибки

```json
{
  "detail": {
    "code": "source_unavailable",
    "message": "Не удалось получить данные YouTube. Ранее полученные данные сохранены.",
    "retryable": true
  }
}
```

| HTTP | Тип |
|---|---|
| 422 | Некорректные поля/границы; `fields` содержит расположение и тип ошибки, без эха входных значений |
| 400 | Источник отклонил запрос, например непринятый page token |
| 404 | Видео/канал/данные недоступны |
| 429 | Квота исчерпана или источник ограничил частоту; причины имеют разные коды |
| 503 | Сервисный источник не настроен |
| 502 | Ошибка источника / недоступный список загрузок |
| 500 | Ошибка сохранения в БД |

Ответы не содержат сырые исключения, URL с ключом или внутренний стек. При неудаче клиент сохраняет предыдущие успешные данные и предлагает повтор соответствующего действия.

## Схема БД и запуск

Версия схемы — 2. Импорт приложения не создаёт таблицы. Startup проверяет версию и колонки, но не мигрирует данные автоматически.

- Новая БД: `python -m app.migrate`.
- Проверка без изменения: `python -m app.migrate --check`.
- Старая SQLite: `python -m app.migrate --backup ../backups/before-v2.sqlite3` после создания каталога резервной копии.
- Существующая резервная копия не перезаписывается.
- Миграция сохраняет строки, удаляет прежний `is_shorts`, добавляет nullable `duration_seconds`, признаки доступности и таблицу подтверждённых анализов.
- ISO-длительность разбирается целиком; некорректная даёт `null`. Известные числовые длительности не стираются менее полным ISO-значением.
- SQLite DDL, backfill и запись версии выполняются в одной явной транзакции. Неожиданная схема отклоняется до записи/commit.

## Подтверждённость

Проверяются подставные страницы источника, сборка запросов настоящего SDK без исполнения, миграция/откат/файловая копия SQLite и ASGI/HTTP-запуск FastAPI. Выполнена ограниченная живая проверка поиска с текстом и без него, пагинации, постфильтров, анализа канала, числовых формул, прямой карточки, кеша и явного обновления: [отчёт](LIVE_TEST_REPORT.md). Фактический квотный баланс и качество выдачи без `q` не оценивались. PostgreSQL не подключался. Это проверенный в ограниченном наборе сценариев backend, не готовый frontend и не подтверждение поведения всего источника.

Документация источника для последующей живой проверки: [search.list](https://developers.google.com/youtube/data/reference/rest/v3/search/list), [playlistItems.list](https://developers.google.com/youtube/data/reference/rest/v3/playlistItems/list), [Video](https://developers.google.com/youtube/data/reference/rest/v3/videos).
