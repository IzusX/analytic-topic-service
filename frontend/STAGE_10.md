# Этап 10 — устойчивость, доступность и адаптивность

## Объём

Этап 9 отправлен по разрешению пользователя: `5da618cbd38cc8c110b44c653b2d9f0b2833ed8d`, удалённый `main` проверен. Этап 10 проверяет существующий сценарий без новых продуктовых функций и без финального редизайна этапа 11.

## Исправленные дефекты

1. **Повреждённые live DTO.** Поиск ранее проверял только id/title видео. JSON-объект вместо published_at мог пройти в успешное состояние и сломать форматирование/сортировку. Теперь live-ответ использует тот же строгий guard потребляемых DTO-полей, что и sessionStorage. Ошибка становится безопасной `invalid_response`, прежние карточки и кеш остаются.
2. **Идентичность первого ответа.** Ранее несоответствующие запросу applied/query могли быть сохранены под чужим ключом; reload отвергал весь кеш. Проверка идентичности теперь работает для search/refresh/more, включая API-only условия, с разрешёнными backend defaults и новой абсолютной границей относительного периода. Explicit bound при продолжении не меняется. Восемь новых тестов покрывают повреждённые поля, search/refresh/more и сохранность reload.
3. **Клавиатурный фокус после последней догрузки.** Если кнопка «Показать ещё» исчезает, фокус переносится на результат обработки страницы без прокрутки. Это покрыто real Vue/jsdom тестом.
4. **Доступные имена формы.** Summary длительности больше не теряет выбранное состояние из-за aria-labelledby, заменявшего полный текст; имя включает назначение и число выбранных групп. Combobox-role и expanded-state языка привязаны к реальному фокусируемому input, а не внешнему wrapper. Ошибка длительности обозначена aria-invalid.
5. **Размер сброса фильтров.** Реальный browser-check обнаружил высоту текстовой кнопки менее согласованных 44 px. Добавлен min-height 44 px без изменения оформления.
6. **Сбой графического движка.** Ошибки init/setOption ECharts не роняют страницу: показывается сообщение с указанием точной таблицы и списка. Экземпляр освобождается, данные анализа сохраняются. Добавлены два lifecycle regression-теста.

Существующие фиктивные ответы нескольких старых тестов приведены в соответствие с реальными отправляемыми условиями. Проверки не ослаблены: восстановленные API-only bounds отдельно сохраняются и проверяются при refresh/continuation.

## Реальный браузер

`npm run verify:browser` теперь проверяет актуальные страницы вместо заготовок этапа 5. Используется установленный headless Chrome и CDP, без новых browser-зависимостей и без отключения защиты Chrome. В workspace-write Chrome не смог инициализировать macOS sandbox/Crashpad; после одобренного расширенного доступа прогон выполнен успешно.

На **1440 / 390 / 320 CSS px** пройдены:

- начальная страница и отсутствие автоматического поиска;
- клавиатурный skip link, native details/checkbox, Enter в query;
- раскрытие мобильных фильтров клавиатурой и синтезированным CDP touch;
- выдача с длинными названиями без пробелов, отсутствующими превью, нулевыми/неизвестными просмотрами и скрытыми подписчиками;
- переход на канал, настоящий ECharts SVG, раскрытие таблицы и клавиатурная горизонтальная прокрутка таблицы на мобильном;
- возврат к поиску с сохранёнными карточками/черновиком/фокусом исходного действия без новых запросов;
- отсутствие горизонтального переполнения документа, проверка высоты целевых элементов;
- отсутствие runtime/console ошибок.

Все API-запросы перехвачены CDP Fetch и получили детерминированные тестовые DTO: **по 1 search и 1 channel на ширину, всего 6 mocked API**, **0 live API responses**, 0 неожиданных API/внешних HTTP-запросов. Неизвестные API и внешние HTTP fail closed. Бэкенд/YouTube не вызывались, квота не расходовалась. Это проверка frontend с fake transport, не end-to-end живого источника.

Независимый read-only finish review проверил diff, отчёт и три ключевых screenshots: материальных блокирующих дефектов в этом ограниченном объёме не найдено. Reviewer не запускал тесты самостоятельно и не выдавал глобальную оценку WCAG.

Получены 12 полностраничных PNG и `frontend/verification/browser-report.json` (игнорируются Git). Названия: search-initial/search-filters/search-populated/channel-loaded для каждой ширины. Native keyboard event dispatch и initial-navigation guards стенда исправлены после обнаружения ошибок самого тестового сценария; production DOM-click обходы не добавлялись.

## Границы доказательств

Пройденный browser-набор — Chromium с эмуляцией ширины и синтезированными клавиатурой/touch, не физические мобильные устройства. Не заявляется WCAG-сертификация, screen-reader audit, Safari/Firefox, 200%-text-only zoom, нагрузочная проверка или доказанное улучшение usability. Сетевые ошибки/квота/отмена/storage/reload/пагинация покрыты unit/jsdom, но не все эти состояния включены в браузерный success-fixture сценарий. Реальные backend и YouTube здесь не проверялись.

Визуальные токены и компоновка наследуются из DESIGN.md. Финальная выразительность хедера, набор иконок и эстетическая полировка остаются этапу 11. Этап 12 — отдельная техническая приёмка и пользовательский сценарный тест. Ни один из них автоматически не начат.
