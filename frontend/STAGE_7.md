# Этап 7 — догрузка, дедупликация и сортировка

Перед началом этапа `bd64589` отправлен в origin/main и удалённый hash проверен. Пользователь сообщил, что этап 6 работает и корректно отображается. Это ручная обратная связь, не автоматический аудит новых состояний.

## Реализовано

- «Показать ещё»: одно действие → один запрос → одна страница до 50 кандидатов. Нет скрытой догрузки до заполнения сетки или автоматического обхода пустых страниц.
- Запрос продолжения берёт applied, token и исходную абсолютную UTC-границу, не draft. Относительный период без сохранённой границы не догружается. Ответ продолжения проверяется на соответствие применённым условиям.
- Карточки накапливаются отдельно от DTO последней страницы. Повторы ID удаляются, первое целое наблюдение сохраняется без смешения полей из разных времён. Исходный порядок воспроизводим.
- Локальная сортировка загруженных: порядок YouTube, просмотры по убыванию, дата от новых к старым, просмотры/подписчики по убыванию. Неизвестные значения в конце, ноль известен; равные значения сохраняют исходный порядок. Сортировка не мутирует source и не вызывает API.
- Догрузка повторно применяет выбранную сортировку. Refresh/новый поиск заменяют накопленную выдачу после успеха, но сохраняют выбранный способ сортировки.
- При догрузке/ошибке старые карточки и draft сохраняются. Retry повторяет точную неудавшуюся страницу. Busy, abort и request-id защищают от дублей и устаревших ответов.
- Пустая/дублирующая страница показывает число добавленных уникальных видео; token сохраняет возможность явного продолжения. Отсутствие token показывает конец; повтор уже использованного token останавливает дальнейшую догрузку.
- Счётчики страниц, проверенных кандидатов и уникальных видео разделены. Время явно подписано как время последней страницы; оно не выдаётся за единый timestamp всей накопленной выдачи.
