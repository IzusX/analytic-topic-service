# Frontend foundation

Основа интерфейса «Аналитика тем»: Vue 3, TypeScript, Vite, Vue Router, Pinia, Tailwind, Naive UI. ECharts строит SVG-график просмотров ограниченной выборки канала с линией медианы.

Работают общая оболочка, маршруты, форма поиска и карточки первой страницы. Запрос выполняется только кнопкой «Искать» или Enter в строке темы, не при открытии/редактировании. Draft отделён от applied; обновление и явный повтор не применяют черновик. Добавлены явное продолжение, дедупликация и локальная сортировка. Сессионный кеш и восстановление контекста реализованы; экран анализа показывает правило выборки, описательные метрики, график и доступные исходные данные. Результаты: [STAGE_6.md](STAGE_6.md), [STAGE_7.md](STAGE_7.md), [STAGE_8.md](STAGE_8.md), [STAGE_9.md](STAGE_9.md).

## Запуск

Нужен Node `^20.19.0`, `^22.12.0` или `>=24.0.0`; проверено на Node **24.19.0** и npm **11.17.0**. Выполняйте команды из `frontend/` внутри полного checkout: TypeScript-типы импортируются из соседнего `backend/contracts/api.ts`.

```bash
cd frontend
npm ci --cache ../.npm-cache --no-audit --no-fund
npm run dev
```

Адрес разработки: **http://127.0.0.1:5173/**. Это отдельный frontend проекта, не DeepSeek Harness GUI. Vite занимает только этот порт; конфликт порта завершает запуск, не подменяет другой сервер.

## API и окружение

По умолчанию запросы клиента идут на `/api` того же origin. В режиме разработки Vite проксирует их в FastAPI на `http://127.0.0.1:8000`. Backend запускается отдельно по инструкции корневого README.

Для другого локального порта:

```bash
API_PROXY_TARGET=http://127.0.0.1:8001 npm run dev
```

Для production укажите публичный origin API в локальном `frontend/.env.local` или окружении сборки:

```dotenv
VITE_API_BASE_URL=https://api.example.com
```

Это пример публичного адреса, не настроенное развёртывание. Значение должно быть origin без `/api`, других путей, query/fragment или credentials. Пустое значение означает same-origin `/api`. Прокси Vite относится только к dev; production требует настроенного API origin либо собственного reverse proxy.

**YouTube-ключ остаётся только в `backend/.env` или серверном окружении. Не добавляйте его в `VITE_*`, клиентский bundle, URL или storage.**

## Типизированный клиент

`src/api/types.ts` реэкспортирует backend DTO только как типы. Они не копируются вручную и не добавляют backend-код в browser bundle. После изменения API обновите контракт командой `python -m app.export_contracts` из `backend/`, затем выполните frontend typecheck.

```ts
import { createConfiguredApiClient } from './api'

const api = createConfiguredApiClient()
// Создание клиента не отправляет запрос. Вызовы ниже — только по явному действию.
const controller = new AbortController()
const result = await api.searchVideos(
  { query: 'python tutorial', limit: 10 },
  { signal: controller.signal },
)
```

`createApiClient({ baseUrl, fetch })` доступен для тестов и явной конфигурации. `createConfiguredApiClient()` читает `VITE_API_BASE_URL` только при вызове, без eager singleton или запросов при импорте.

Методы: `searchVideos`, `getChannel`, `getVideo`. Контекст канала передаётся как `sourceVideoId`, явное обновление — `forceSync`; клиент преобразует их в параметры backend. Прямой API видео не создаёт обязательную frontend-страницу видео.

Один вызов метода — один `fetch`. Точные `.`/`..` в resource ID отклоняются до построения URL и fetch, чтобы native URL не заменил адрес ресурса на родительский путь. Нет автоматических повторов, авторизации, custom-header API, cookies или application cache. `AbortError` отличим от сетевой ошибки. `ApiError` хранит безопасные сообщение, код, HTTP-статус, retryable и ошибки полей; raw network/proxy/HTML/debug текст не используется как пользовательское сообщение. Успешный JSON проверяется только на верхний объект: типы не являются полной runtime-валидацией DTO.

## Маршруты

- `/` — рабочая форма поиска и первая страница выдачи.
- `/channels/:channelId` — анализ канала: переход загружает конкретный анализ при cache miss. `?videoId=<id>` задаёт контекст исходного видео без изменения ключа общего анализа; смена только этого контекста не отправляет запрос.
- Неизвестный адрес — техническое состояние «Страница не найдена», не новый продуктовый раздел.

Нет `/settings`, каталога каналов или обязательного `/videos/:id`. При сохранённой выдаче ссылка канала называется «К результатам поиска», иначе — «К поиску». Возврат восстанавливает прокрутку и фокус исходного действия после отрисовки, без API-запроса.

## Проверки

```bash
npm run typecheck
npm test
npm run build
npm run preview
```

Последний полный прогон этапа 9: **403 теста прошли**, `vue-tsc`/`tsc` и production build прошли. Проверяются API-маршалинг и ошибки/отмена без сети, конфигурация, отсутствие eager запросов, dot-segment ID, базовые маршруты/фокус в jsdom и контраст заданных токенов. `dist/` не коммитится. Проверка production-зависимостей через официальный npm audit вернула 0 vulnerabilities; это не полный security-аудит приложения.

Браузерный стенд подготовлен отдельно:

```bash
npm run verify:browser
```

Он рассчитан на установленный Chrome в текущей macOS; `CHROME_PATH` задаёт другой путь, `FRONTEND_URL` — локальный адрес frontend. Новые browser packages не устанавливаются. Стенд проверяет 1440/390/320 px, маршруты, длинные ID, фокус, клавиатурные переходы и отсутствие API/внешних запросов. Результаты должны попасть в игнорируемый `verification/`.

**Реальный браузерный прогон сейчас не подтверждён:** Chrome остановился при инициализации своей sandbox/Crashpad из-за файлового ограничения `workspace-write`. Скриншоты и `browser-report.json` не получены; jsdom-тесты не заменяют проверку рендера, touch и клавиатуры в браузере. Защита Chrome не отключалась.

## Границы готовности

Рабочий поиск первой страницы технически проверен, но весь сценарий поиска/анализа ещё не завершён. Три ограниченных живых запроса через настоящий клиент/store и dev proxy прошли; результат и стоимость описаны в [STAGE_6.md](STAGE_6.md). Повтор: `RUN_LIVE_SEARCH=1 npm run verify:live-search` — это opt-in с расходом YouTube-квоты, не часть обычных тестов.

Pinia/sessionStorage сохраняют до 5 поисков и 10 анализов, суммарно до 3 МиБ UTF-8 JSON. Неактивные записи вытесняются по LRU; активный снимок сверх бюджета остаётся только в памяти. Ошибки storage не блокируют поиск, но перезагрузка может потерять состояние. Одинаковый явный поиск использует кеш, включая замороженную границу относительного периода; свежие данные запрашиваются через «Обновить выдачу». Сохраняются raw draft, applied, все загруженные карточки, порядок/сортировка, продолжение и прокрутка. Страница канала вызывает аналитический store только для выбранного канала, не для всей выдачи. Повтор открывается из кеша, «Обновить данные» вызывает force_sync; ошибка сохраняет прежний снимок. Правило >180 секунд / до 30 видео / максимум 200 загрузок и 4 страницы видно рядом с фактическими размерами/ограничениями. Основные и дополнительные метрики используют backend-снимок; SVG-график дополнен точной таблицей и списком видео. Догрузка по applied и локальная сортировка работают без скрытых запросов. Повторы ID сохраняют первое целое наблюдение; timestamps разных страниц не являются единым снимком. Исходное видео отмечается только при подтверждённом включении в выборку. Известные причины исключения объясняются без сравнения с неподходящей медианой. Новых живых API-проверок на этапе 9 не выполняли; реальный ECharts проверен через SVG SSR, а не скриншоты браузера. Браузерный рендер/доступность/адаптивность и финальная выразительность хедера остаются открытыми. Старый browser-стенд этапа 5 нужно расширить для новой формы и карточек; его проверки не объявляются актуальной приёмкой этапа 6.
